## Answer first

**Hold the tag for one task and the text. Nothing else blocks.** Neither deep dive found a bug on obor-kit's own
Claude and Codex path.

Before the tag:

1. **agy's tool table binds sessions it should not, and `obor stop` does not lift it** (Opus F3, agy B2 and B3; Q2).
   v0.44.1 moved three deny rows and the unknown-tool deny into the agy transport, which knows neither the session's
   role nor whether the project is stopped. So the owner's own agy session in the project loses subagents, workflows
   and any new agy tool, and `obor stop` does not give them back, although a stopped project is "no project" to
   every other hook (`internal/guard/load.go:15`). The only way out is editing a protected file. v0.44.0 did not do
   this: its three matchers all went to the guard. Fix: the transport sends these calls to the guard, which
   already knows role and stopped. One task, medium (agy live tier). The guard's empty-argument allow (Opus F2, Q1)
   is ~5 lines in the same file and rides along.
2. **Text:** the v0.44.1 section of `docs/UPGRADE-v0.44.md` (draft in §4), three v0.44.0 lines there that are now
   false, five passages of `docs/design.md` that contradict this wave's own tasks (agy B9), and the README, which
   never names agy (Opus F13).

If the tag cannot wait for task 1: ship the stopped check alone (6 lines in `InProject`, `hook.go:372-387`) and say
in the guide that the owner's own agy sessions are bound until v0.44.2.

The verdicts compared: Opus says ship after text and two small items; agy says hold for four bugs. Of agy's four,
B2 and B3 are the one task above. B1 (a kind call under `App.mu`) and B4 (Codex quoted server names, reproduced in
Q3) are real and belong in the next wave. Opus saw the same blocker and left it to the owner as a question; my
answer to that question is that it is not wanted.

The decisions, short (details in §5):

- **The owner's own agy sessions:** not bound. The 11-22 decisions and BACKLOG all say "obor agents"; nothing
  decided the owner's sessions. The rule moves to the guard: an agent with a role is denied, a role-less session in
  the main checkout is not.
- **`App.mu` and kind calls (Opus F1, agy B1):** each reviewer found one half. Both halves disappear for the kit's
  kinds once they are linked into obor (decided 11-22), because a linked kind never describes and its `turn` is a
  function call. Do the link-in first; what is left is for third-party kinds only.
- **OpenCode denies unknown tools, like agy (Opus F4):** right direction, but not ~15 lines. OpenCode hands MCP
  tools to the plugin under plain tool names, so a deny-by-default there needs a probe first, or it denies obor's
  own tools.
- **The nightly agy tier records a failed run (both):** record only a green run.
