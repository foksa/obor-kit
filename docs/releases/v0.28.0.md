Steadier under load and fewer hand steps: gates skip re-runs that cannot matter, agents come back after a stop, and serve requests the reviews a spec asks for.

- **Fewer gate runs:** a green task whose target moved keeps its result when the new commits touch none of its files or
  packages (marked `kept` and partial; the nightly full check covers the rest), and pane events no longer scan every
  lane's git.
- **Workers come back:** a working task whose worker stopped or crashed gets its worker back with its job, and
  `obor stop --force` keeps open tasks open: `obor start` continues them. Any `obor pause` holds that restart.
- **`Review: on merge`:** a spec line that makes serve request a review once the task merges, instead of a watch and a
  hand-run `obor review`.
- **MCP server on the official Go SDK:** obor's MCP tools run on the Model Context Protocol's Go SDK, checked live
  against Claude Code, Codex and OpenCode as obor launches them.
- **One shape per task, session and pane:** `obor status --json` has one `tasks` map keyed by id that the lanes, queue
  and needs-you entries reference; obor web shows the same title and state everywhere.
- **A lane whose git or store read fails is never free,** keeps its task's open questions, and its idle and stall
  timers restart once it reads again.
- **Reviews close honestly:** a close that accepts findings says `accepted <n>` instead of `approved`.
- **Removed config keys:** `merge.timeout_grep`, `merge.max_load`, `merge.load_wait`, `merge.window_wait`,
  `slots.merge_block_max`, `integrator_handoff_tokens`, `stop_idle_workers`, and the empty `mcp` and `cache`
  sections (a warning names them).
