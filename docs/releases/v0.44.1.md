obor's hooks see every agy tool, and lane workers of every kind use only the project's MCP servers.

- **agy:** obor's hook matches every tool; workflows, swarms, subagents and tools obor does not know are denied for obor agents (never your own session in the main checkout, never in a stopped project). A start refuses a workspace whose `.agents/hooks.json` is stale: projects with agy run `obor setup agents` and commit it. A resume reads no model list; a failed live list uses the last good one. Lines go only through `agy` on PATH to a local address.
- **MCP servers in lanes:** workers and drives of every kind load the project's declared servers plus obor's, none of the user's (Claude's approved `.mcp.json`, Codex `.codex/config.toml`, OpenCode `opencode.json`, agy `.agents/mcp_config.json`, the last enforced by the guard).
- **Guard:** a write with no file or a command with no text is denied; a hook binary that crashes denies the call; `opencode acp`/`serve` are headless runs.
- **OpenCode:** the plugin fails closed, a resumed session binds its inbox at start, a subagent's session is never the agent's, and a turn end dates the agent's activity.
- **Serve:** no kind call under its main lock in the handoff rule; a lead line counts as handed only before the hook's deadline; a dead inbox socket sends lines through the hooks.
- **CLI:** `obor status` exits 1 when serve's socket is refused (a sandbox); `obor whoami --json` has `lines`; `obor setup mcp` checks every kind a model names.
- **Nightly:** agy's live conformance tier runs when `agy --version` changed.
- **Docs:** older release notes, upgrade guides and finished research are gone from the tree (their tags keep them).

Upgrading: a project with an agy model runs the step in `docs/UPGRADE-v0.44.md` (v0.44.1); OpenCode agents restart onto the new plugin.
