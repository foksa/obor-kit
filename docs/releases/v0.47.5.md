A raised lane count just works: serve adds the new lanes' worktrees itself.

- **New lanes:** raising `lanes.count` (in `.obor/config.json` or on the web Setup page) is enough. Serve adds each configured lane whose worktree is missing, as `obor setup lane` does (worktree, links, `lanes.setup`). Until its setup succeeds the lane takes no task, also across a serve restart; a failed setup is a needs-you naming the lane, the error and `obor setup lane <LANE>`, retried with a backoff. A lane holding a task is never touched.
- **Reviews:** the probe line in review and deep dive briefs agrees with the role texts: a sandbox that cannot write the shared Go cache (Codex) puts one under the probe dir, so its tests run.
