The old config shape goes, setup names the reason a config does not load, and a README that matches obor as it is.

- **Config shape 1 is refused:** a `.obor/config.json` without `"version": 2` fails every load with one error naming the file and the way out (migrate it with obor v0.33, then upgrade). The one-release reading window, serve's automatic rewrite and `obor config migrate` are gone.
- **Setup says why:** `obor setup show`, `setup lane`, `setup agents` and the other setup commands pass a config's own load error on instead of "no usable config, run obor init".
- **README:** lanes as a pool picked by difficulty, the target branch, where tests run, reviews, the OpenCode kind binary, and the first commands a new user needs.
- **obor web:** "queued for a lane" no longer counts dispatches still waiting for the tasks they run after.

Upgrading: check that each project's config says `"version": 2` (the block in `docs/UPGRADE-v0.34.md`); a project still on shape 1 migrates with obor v0.33 first.
