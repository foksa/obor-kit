Fewer steps to remember: fix tasks link themselves to their review, hard tasks are reviewed on merge, and serve restarts itself one safe way.

- **Fix tasks link themselves:** a `Fixes: RV-<n>` line in a fix spec links it to the open review, and serve runs the
  verify in the same reviewer session once the fixes merged; `obor review fix` is gone.
- **Hard tasks are reviewed on merge** without a spec line; a fix task is reviewed by its verify instead.
- **Review close runs in serve:** serve commits the close and stops the reviewer at once; only the lead may close,
  and a failed commit keeps the review files and `BACKLOG.md` as they were.
- **One automatic restart:** serve follows a new binary and never restarts while a config edit or review close is
  committing; `commands.after_merge.restart_serve` is removed.
- **The guard's load-run rule is configurable:** `guards.deny_commands` replaces the built-in Go rule.
- **A drive is new work only:** taking over a worker's task with `obor drive` is gone; so is `obor projects --notify`.
- **Fewer gate runs:** a clean move that shares only packages re-runs only the compile steps, and a resolved conflict
  is reused when the target moves.
- **Steadier status reads:** status fields from an older serve read as the safe answer during an upgrade.

Upgrading: close open reviews, re-run the installer, `obor config validate`, restart every serve, then its agents.
