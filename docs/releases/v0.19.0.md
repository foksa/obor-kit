Effort is now part of every agent choice, a spec can name its lane type, and opencode lanes run isolated.

- **Effort beside the type:** write `opus:high`, `sonnet:low` or `deepseek:high` anywhere a lane type is named: a spec's `Type:` line, `obor dispatch --types`, the config's difficulty lists and role types. obor applies it when it starts the agent: Claude's `--effort`, Codex's reasoning effort, opencode's model variant.
- **Lane type in the spec:** an optional `Type:` line under `Difficulty:` picks the lane type; when none of it is free, the task takes the level's first free lane.
- **Isolated opencode lanes:** every opencode agent obor starts gets its own state directory, so the model and effort obor asks for are the ones it runs, and your own opencode settings are never touched.
- **`obor setup show`** prints the effort per difficulty and role.
- **Monitor:** only failed events are red; a passing gate no longer looks like an error.
- **Faster checks:** the kit's own test suite runs in about 115 s instead of 158 s, and its core package is split into smaller ones.

Upgrading: opencode lane types without a `--model` (and no `opencode.json` model) must name one now. Then re-run the installer and `obor serve restart` in each project. Details in `docs/UPGRADE-v0.19.md`.
