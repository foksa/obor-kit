Every start checks who already runs before it touches a pane, the terminal sits behind one interface, and a running review is visible.

- **Start identity:** `obor restart`, `obor lead`, `obor setup`, `obor drive` and serve's starts ask serve which pane already runs the agent (by session, start record or label) before any stop, label or typed line. A relabelled agent is recognised instead of duplicated; a start that would make a second copy is refused, naming the pane and a command that works.
- **Serve down:** a start that would add an agent is refused while an unlabelled live agent sits in the project; the refusal says how to go on.
- **Review visibility:** `obor status` and `obor web` show an open review's stage, its tasks, the reviewer and the stage's age; the fleet page badges a project under review.
- **Terminal interface:** herdr is built in one place and spoken to through obor's own operations and errors; `obor status --json` names it `terminal` / `terminal_note` (were `herdr` / `herdr_note`); messages and hints name obor commands.
- **Recovery messages:** herdr's stale-name retry and a failed clear are reported again, in serve's log for its own starts; first-start hints say `--fresh` when there is no session yet.
- **Init:** places the panes of the configured lanes, whatever their names.

Upgrading: nothing to do; tooling that reads `obor status --json` should read `serve.terminal`. See `docs/UPGRADE-v0.38.md`.
