The nightly runs every night while it is on, and the lead switches it with one command.

- **The nightly runs every night while on:** serve no longer skips a night when every merge since the last full check
  ran the full gate. The nightly runs more than the merge gate (check_milestone, the baseline, the forced gate, e2e, the
  store backup), so while `merge.nightly_at` is set it runs every night at that time; unset, never.
- **`obor nightly on HH:MM` / `obor nightly off`:** the lead or the owner switches it (`NIGHTLY ON at HH:MM`,
  `NIGHTLY OFF`, `… already` when nothing changed). Serve writes `merge.nightly_at` as a setup edit, one commit on
  main, and reads it from its next pass: no serve restart. `obor nightly` with no argument still runs one now.
- **`obor status`** shows `nightly: off (obor nightly on HH:MM)` when it is off.
- **Switched off, a RED still clears:** a GREEN `obor nightly` run by hand ends the RED's needs-you whether the
  nightly is on or off; off stops only new runs.

Upgrading from v0.24.0: nothing required; a project with `merge.nightly_at` set now runs its nightly every night (`obor nightly off` to stop it). See `docs/UPGRADE-v0.24.md`.
