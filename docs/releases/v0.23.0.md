The config names models directly: no lane types, no caps, lanes are a count.

- **Model refs**: `difficulty` levels and `roles` name a model with its effort (`"hard": ["opus:medium"]`,
  `"reviewer": "terra:xhigh"`). obor knows opus, sonnet, haiku, fable, deepseek, terra, sol and luna and each agent
  kind's base args and effort flag; `kinds.<kind>.args` adds a project's own args, `models.<name>` adds or overrides
  a model. A level's first model is the default; a spec's `Model:` line (was `Type:`) or `obor dispatch --model`
  (was `--types`) puts named models first, and `obor pause --model <name>` skips one.
- **No caps, pooled lanes**: `"lanes": N` gives L-01 … L-NN, each running the model its dispatch picks. `lane_types`,
  typed lanes, `max` and role objects are gone.
- **`obor setup migrate`** rewrites an old config once and commits it; the loader refuses the old shape after that.
- **Setup page** (obor web) edits the new shape: model chips per level, model and effort per role, the lane count,
  and a pause per model.
- **Project list**: a project whose config does not load (an older or newer obor) stays on `obor projects`, `obor
  send` and the web fleet instead of being dropped.

Upgrading from v0.22: migrate each project's config; see `docs/UPGRADE-v0.23.md`.
