Lanes become a pool, serve and its views follow new binaries by themselves, and reviews run in the main checkout with merges held while they work.

- **Lane pool:** a lane may be untyped (`"lanes": {"L-01": ""}`); each task's `Type:` and `Difficulty:` pick its model and effort at dispatch, and any free untyped lane takes it. Typed lanes stay reservations. `lane_types.<type>.max` now caps open worker tasks of a type at dispatch; role agents never count.
- **Follows new binaries:** serve, `obor monitor` and `obor web` notice a new obor binary and restart themselves on it within a minute, so a release needs no hand restarts after this one.
- **Reviews in the main checkout:** the reviewer and deep dive read the main checkout; serve holds merges while either works (at most 30 minutes). Start them with `obor brief` (a brief to a stopped role starts it fresh); `obor restart <reviewer|deep-dive> --prompt` is refused. `obor review verify` and `obor review close` run the verify and close steps in one command each.
- **Smaller fixes:** a fresh lead restart starts its skill by itself; a brief whose agent was stopped no longer stays open; full checks wait while the machine is overloaded; releases keep their own log and rerun a failed test package once; `obor init` lists only providers it detected; the reviews folder is gitignored by `init` and role setup; the web page shows agents' long-running processes.

Upgrading from v0.19: this once, after the installer, run `obor serve restart` in each project and restart its `obor monitor` and `obor web` panes (v0.19 cannot follow a new binary yet). Then follow `docs/UPGRADE-v0.20.md`: restart the reviewer (and deep dive) into the main checkout, remove their old worktrees, and pool lanes if you want.
