obor answers its own agent kinds (OpenCode, agy) itself, lanes of every kind keep to the project's MCP servers more strictly, and OpenCode's tools are classified one by one.

- **Kinds:** the kit's OpenCode and agy kinds run inside obor; no `obor-kind-*` binary runs (this is the last release that ships them). `obor init` writes no `plugin` line for them; a third-party kind is an external command as before.
- **MCP servers in lanes:** Codex matches server names with a space or a dot and refuses a lane's args that set a key under `mcp_servers`; Claude leaves out a server `disabledMcpjsonServers` names; an OpenCode override's `null` leaves a user server off.
- **OpenCode:** a tool obor has no rule for is denied for obor's agents by name; MCP tools pass when OpenCode reports their server connected; `opencode_worktree_create`/`_remove` are checked as git worktree writes; `opencode api` is a headless run; a root turn's end creates the token file.
- **agy:** an empty `agy models` answer takes the last good list; a fallback that is no timeout warns; a refused delivery says why. With no usable obor binary, its hook denies tool calls only in a running obor project (a lane resolved to its main checkout) and leaves every other repository to agy. agy 1.5.15 needs nothing.
- **Setup:** `obor setup mcp --model` only checks; it writes nothing.
- **Serve:** a lead's lines are not handed to a hook within 250 ms of its timeout; the project is not idle while any role agent works a brief.
- **Web:** a role agent working a brief (deep dive, advisor, researcher, designer) shows as a card like the review's.
- **Nightly:** agy's live tier records its version only after a run with passing rows and no failed or skipped one.
