`obor init` sets up every configured lane, a cut step no longer retries in a tight loop, and serve's log stays readable.

- **Init and lanes:** `obor init` sets up every lane the config names (`lanes.count` or `lanes.list`) and places the first two lanes' panes from the same list, so a re-init with more than two lanes leaves none missing.
- **Retries:** a step cut while serve keeps running waits before its next try, with a growing delay, instead of retrying as fast as a lane scan.
- **Review close:** commits the project's `BACKLOG.md` wherever it lives, and only when git tracks it.
- **Serve log:** serve's own lines and its app's no longer interleave.
- **Agent texts:** workers never generate machine load to reproduce a flake and stop what they start; the deep dive probes without git writes.
- **Tests:** faster, steadier suites (fewer git processes, in-process fakes); the test budget warns on time and fails on git processes and leftovers.

Upgrading: nothing to do; see `docs/UPGRADE-v0.37.md`.
