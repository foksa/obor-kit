Monitoring: see what is running and what is queued, in the terminal and in a browser.

- **`obor web`:** a read-only page at `http://127.0.0.1:8787/` for every obor project on the machine. It shows what needs you, work in progress, the queue (merge pipeline, waiting dispatches, review cycle, watches) and recent events. Per task it shows the spec, report, gate, timeline and the prompts its agents got; per agent its sessions, briefs and jobs. Localhost only, no actions.
- **New `obor monitor`:** sections, state colours and a spinner, drawn on the alternate screen, so it fits the pane and never pushes your scrollback. It now also lists tasks waiting for a lane.
- **Prompts are recorded:** serve keeps the text of every job, brief and start prompt it sends (one row per distinct text, 14 days), so you can read exactly what an agent was told.
- **One read model** behind `obor status`, `obor monitor` and `obor web`. `obor status --json` adds `roles`, `queue`, `events` and per-lane `spec_rev` and `job`. The queue states facts (who holds the merge, each task's stage), never a guessed next task.
- **`running:` is honest:** it lists only work executing now, with the command actually running; stuck work shows as `pending`.
- **`obor watch T-a,T-b --note "…"`:** the merged line carries your note, so the reminder of what to do next arrives with it.
- **Role agents stop when done:** serve stops the integrator after each job and the reviewer when its review closes; the lead stops the advisor and deep dive. A brief to a stopped agent starts it fresh. Less memory held by idle agents.
- **Shorter worker jobs:** each rule is said once; a work job went from about 11k to 9k characters.

Upgrading: re-run the installer, then `obor serve restart` in each project and restart its monitor. Details in `docs/UPGRADE-v0.18.md`.
