The lead reads any agent's pane on every terminal, gets a task's report in one command, and is told its terminal's own manual.

- **`obor read <agent> [--lines N]`:** an agent's pane through the project's terminal (herdr, hc, Rex), so a Rex lead sees a permission prompt or a dialog too. The lead skill uses it instead of `herdr pane read`.
- **`obor spec show <T-xx> --report`:** the task's latest `task_done` report, merged or not; for a task without one it says why (none yet, dropped or merged with none, or older than the log's 30 days).
- **Terminal manual:** `obor whoami` prints a `terminal:` line with the terminal's own manual command (`herdr --skill`, `hc --skill`, `rex skill show`); the lead skill says to read it only for what obor does not do, and that obor alone starts, stops and messages its agents.
- **Quieter status:** a free lane shows `(last T-xx)` instead of a stale branch; a dispatch reply says `(starting)`; Rex's API revision skew prints in `obor setup show`, not in every `obor status`.
- **Worker role:** scratch files go through the file-write tool; no heredoc file writes and no `rm` in compound commands (they stop on a permission prompt nobody answers).
