Draft (lead; finish at release).

- **obor web Setup page** (`#/<project>/setup`): difficulty levels with what each type runs (model, effort, max;
  unused types marked), lanes (pooled or typed), roles and the pause, and how dispatches spread by level and type over
  7 days or all time (T-750, T-752).
- **`obor drive` / `obor land`**: the owner iterates by hand on a task's branch in a plain interactive agent, then lands
  it through the gate, review and merge; `obor drive T-xx` takes over a task in progress (T-751).
- **Setup edits from obor web:** the Setup page edits a difficulty level's types (reorder, add, remove), a lane type's
  model, effort and max, a lane's type, a role's type, and sets or clears the pause. Serve validates each change, writes
  `.obor/config.json` and commits it on main (`config: <key> <old> → <new> (owner, web)`), and the lead gets the same
  line; a config with uncommitted changes or a lane with a task is refused. Edits are taken only from the page's own
  origin on localhost (T-753).
