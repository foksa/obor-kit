Shorter waits for a merge: each task's tests run in its own lane, in parallel, and serve's merge slot only merges and compiles.

- **Tests run in the task's lane:** the class's checks run in the lane at the merged candidate, several lanes at once; the merge slot merges and compiles in seconds. Check receipts and the machine-load wait are gone.
- **A CPU budget per lane:** every Go process in a lane runs on `slots.lane_cpus` cores (default 2), agents and lane tests alike.
- **A red test is retried once:** a red lane test re-runs only its failing tests before it counts; a pass is recorded as a flake.
- **Several classes, each class's checks:** a lane that touches files of several `merge.classes` runs each class's checks instead of the whole suite; a full lane also runs the checks of classes marked `with_full`.
- **Optional staging and promotion:** with `branches.promote` set, tasks merge into a staging branch and serve moves `main` only to a commit covered by a closed review with a green full suite, in batches weighed by difficulty (`merge.promote_weight`). Off unless configured.
- **herdr's waits instead of polls:** starting and stopping agents waits on herdr's own events, and obor no longer renames herdr agents back.
- **Clearer status:** a paused model shows in `obor status` and `obor setup show`; the web monitor shows staging, the promotion and main as a line of info.
- **Old record shapes dropped:** compatibility code for record shapes no store still holds is removed (upgrade from v0.29).

Upgrading: see `docs/UPGRADE-v0.30.md` (re-run the installer, `obor config validate`, restart every serve, then its agents).
