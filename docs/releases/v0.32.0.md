Fewer moving parts in the merge flow: the staging→main promotion and three reserved check commands are gone, and a config key obor does not know never stops a command.

- **Promotion removed:** tasks merge into `branches.main` as before; nothing promotes a second branch any more. The nightly tests the target's head, and `main` moves when you release. `branches.promote`, `merge.promote_weight` and `merge.weights` are gone, and so are `OBOR_PROMOTION` and `OBOR_ROOT`.
- **`commands.baseline`, `gate` and `e2e` removed:** they are no longer run by name. Name a command in a merge class's `checks`, `merge.guard` or `merge.nightly_commands`, or use `check_milestone` for the nightly's long tier. `obor config validate` warns about one that is set but never run.
- **Unknown config keys warn, not fail:** serve, every CLI command, the hooks and pane restore ignore a key this obor does not know with one warning; only `obor config validate` refuses it, naming the key to delete.
- **A new project gets a nightly:** `obor init` writes `merge.nightly_at: "02:00"` and an empty `commands.check_milestone` (the nightly's long tier), and says that `commands.check` is the per-merge check, kept to a few minutes.
- **Event kinds from serve:** every event in `obor events --json` and the web carries its kind (merge, gate, dispatch, message, problem…), so integrations and the web's filters no longer parse line wording.
- **Test budget per package:** `go run ./tests/budget -seed <pkg>…` measures only the named packages (relative paths and `./...` patterns resolve to import paths), and the gate fails a new test package that has no budget entry, naming the command to run.
- **The OpenCode default stays one more release:** a config without `kinds.opencode.command` still runs the kit's `obor-kind-opencode` until v0.33.0.

Upgrading: run the block in `docs/UPGRADE-v0.32.md`; it deletes the promotion keys and the baseline/gate/e2e commands if your config still sets them. A project without them needs no change.
