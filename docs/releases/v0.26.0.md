Consolidation: a needs-you is one block on the task's phase, old config keys and stores go, the main checkout is guarded.

- **Needs-you as a block:** a task blocked on the lead keeps its phase; one block (due or held) replaces two states, and
  old logs replay to the same result.
- **Old config refused, not ignored:** keys removed in v0.11–v0.17 are unknown keys now; a pre-v0.23 config is refused
  by every reader, serve and hooks included.
- **Stores from v0.22 on:** older stores upgrade through v0.24 first.
- **Main checkout guarded:** only the lead moves HEAD there; other roles read commits with `git show`/`git diff`.
- **Version on every call:** serve names a caller running another obor in its refusals and its log.
- **CLI deadlines:** dispatch, drop and drive wait for the agent's stop; a call past its deadline says so.
- **Removed:** `obor monitor`'s notice, the pre-v0.23 config message, setup's retire step for the global opencode entry.
- **Smaller, faster test suite:** coverage-redundant tests pruned package by package, each package at its earlier
  coverage.

Upgrading: see `docs/UPGRADE-v0.26.md` (run `obor config validate` in each project first, then restart every serve).
