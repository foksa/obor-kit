Model names now mean exactly what your config says: a new model, a new version or a variant is a config line, not an obor release.

- **Models in config:** `agents.models.<name> {kind, id}` is the only model table. Name versions and variants as you like (`opus-4.6`, `opus-1m`, `atra`) and use them in levels, roles, `Model:` lines and `--model`. An unknown name is refused with the entry to paste.
- **Upgrade:** run `obor setup agents`: it adds the entries your config used from the old built-in list; commit `.obor/config.json`. `obor init` writes the models of the CLIs it finds.
- **Nightly:** tests the head of `merge.target_branch`, whatever branch the main checkout is on.
- **Web:** the fleet page polls projects once instead of twice; `obor web` asks each project's own terminal (hc projects get process info).
- **OpenCode:** a lead's and a worker's generated config no longer share one file.
- **Guard:** denial texts name the real config keys; a guard that fails open says so on stderr.
- **Tests (contributors):** `cmd/obor`'s lead tests no longer wait on a stopped serve; repeated rows went where a lower test holds the decision.

Upgrading: run `obor setup agents` in each project and commit `.obor/config.json`. See `docs/UPGRADE-v0.43.md`.
