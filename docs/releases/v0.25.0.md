obor derives every agent's name instead of storing it, keeps inbox records in the project, and drops the one-time
migrate command.

- **Derived identity:** `OBOR_AGENT` is gone; an agent's name comes from its role, its lane and the config, so a
  rename or a reused shell can no longer leave a stale name. A caller with no identity is refused with the reason.
  Triage has a role like every other role.
- **Inbox per project:** session inbox records live in `.obor/state/inbox/`, so projects with the same prefix never
  collide. After upgrading, remove `~/.obor/agents` and `~/.obor/inbox` and restart role agents and the lead.
- **Pushes:** `guards.allow_push` lists roles, and the git pre-push hook honours it (no `OBOR_ALLOW_PUSH=1` needed for
  a listed role); `obor setup rename` keeps old entries working.
- **One way to brief:** `obor brief <agent> [--fresh] "<text>"`; serve stops and restarts the agent only after it
  accepts the brief. `obor restart --prompt/--type/--effort/--sid` are gone.
- **One task phase** shown the same in `obor status`, obor web and the pipeline; `held` means the integrator's verdict.
- **Specs:** titles from `# T-xx: title`, `obor spec set` refuses an untitled spec; dispatch refuses a merged task.
- **`obor setup migrate` is gone:** migrate an old config with v0.24 first.
