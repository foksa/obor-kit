A lane's first dispatch starts in the pane labelled for it, even after its old pane was closed.

- **Dispatch uses the lane's labelled pane:** serve chose a lane's pane by its cwd and the agent it had seen there,
  ignoring the herdr label, so a pane made with `obor setup pane L-0N` lost to another pane in the lane's worktree and
  the start failed with `pane … is already labelled …`. The labelled pane now wins; a pane labelled for another agent
  is never used.
- **A start whose pane was closed chooses again:** a pending start no longer aims at its recorded pane once herdr no
  longer lists it. If the replacement pane already runs an agent, serve asks you (`needs-you{start: cannot tell …}`)
  instead of starting a second worker over it.
- **A relabelled pane is seen:** herdr sends no event for a rename; serve's recheck of a lane's panes now reads the
  label with the cwd, so relabelling the lane's only pane by hand no longer leaves its dispatch waiting forever.
- **`no-plugin` waits after a start:** an opencode lane is flagged only 2 minutes after its last start, since the
  plugin checks in on the session's first event.

Upgrading from v0.24.1: nothing required.
