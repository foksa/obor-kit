obor keeps every project it knows, four obsolete aliases are gone, and the lead has one verb for its word to a
task, every task command by task id.

- **The project list never prunes:** a register (`obor serve`'s start, `obor init`, `obor start`) only adds or
  replaces that project's own entry. A project that is unloadable, moved or missing for a moment keeps its entry,
  and `obor projects` / `obor send <name>` leave a stale one out when they read. A project lost by the old prune
  comes back at its next init or serve start.
- **Removed aliases:** `obor serve status` → `obor status --facts`; `obor milestone-check` → `obor nightly` (the
  integrator runs it before a milestone merge into `main`); `obor setup opencode-plugin` → `obor setup agents`;
  `obor lead --fresh` is gone (a no-op: `obor lead` starts fresh, `--resume` continues its last session).
- **No roster files:** `obor init` writes no `docs/agents/roster.md`; who runs now, and in which lane, is
  `obor status` (or obor web).
- **`obor resume <T-xx> ["<text>"] [--regate|--sendback]`**: replaces `obor answer` and `obor sendback`. Serve picks
  the action from the task's state: a worker's question gets the answer, a stalled or stopped worker or a drive the
  line, a green or reviewed task the sendback, a needs-you what its cause takes (a hold your decision, a failed step a
  retry, a gate failure a re-gate). Flags only where two actions fit: red past K takes `--regate` or `--sendback`, a
  Blocked report `--regate`. The `regate`/`reprompt`/`retry` words are gone: every needs-you line names the form to
  run.
- **Task ids only**: `obor drop <T-xx> "<why>" [--discard] [--force]` stops the task's worker and frees its lane;
  `obor drop <LANE>` and `obor sendback <LANE>` are gone.
- **`obor monitor` is gone:** obor web and `obor status` show the same view; the monitor's pane, its "system" tab in
  `obor init` and `obor setup monitor` are gone. `obor monitor` prints one line naming its replacement for one minor
  release.

- **Move a task to another model:** `obor dispatch <T-xx> --model <ref>` on a working task stops its worker and
  starts the new model on the same lane and branch, with the task's next attempt (and any outstanding fix text).
  Restarting a lane agent whose lane holds a task gives it the task's job; with serve down it refuses instead.
- **No `agents` config key:** advisor, researcher and triage are roles. `obor setup migrate` moves an entry named for a
  role (`triage`, `fable-advisor`) to that role with its model and relabels its pane; anything else is listed with the
  line to add by hand.
- **Derived names only:** a worker is `<prefix>-<lane lower>`, a role `<prefix>-<role suffix>`; the configurable-name
  aliases are gone.
- **Releases check the upgrade:** `make release` installs the new build over the previous release in two scratch
  projects and runs the upgrade guide's steps before tagging.

Upgrading: run `obor setup migrate` if the project still has `agents` entries; close the monitor pane (`<prefix>-monitor`) in each project's herdr workspace. Details in `docs/UPGRADE-v0.24.md`.
