obor ships one binary: its OpenCode and agy kinds are linked in, agy's hook runs in obor's own process, and `obor config validate` catches lane args a start would refuse.

- **Kinds:** no `obor-kind-*` binary is built, shipped or fetched; a config naming one runs the linked kind. An in-process kind leaves no manifest file, and the sweep removes the old ones. The live conformance tier runs the linked kinds.
- **agy:** `obor kind agy hook` runs obor's hook in process (one obor start per tool call after the shim, not two) and finds the project the way the guard does, so a repository nested in an obor project is its own. Only `slug<TAB>label` lines of `agy models` are models; a fallback to the cached list warns unless the live call timed out; a refused model names the list; `agentapi send-message` runs in its own process group.
- **Validate:** `obor config validate` asks each kind whether a lane's start would refuse its args (FAIL for a worker level's model, WARN for a role's); Codex reads `-ckey=value`.
- **OpenCode:** a lane's agent starts without `OPENCODE_CONFIG_CONTENT`; the pane's shell keeps it.
- **Guard:** a shell command its parser cannot read is recorded in `.obor/state/unparsed.jsonl` and still allowed.
- **Conformance:** the live tier WARNs each CLI tool obor has no rule for; OC-L6 passes on opencode 2.2.0.

Upgrading: see `docs/UPGRADE-v0.46.md` (run `obor config validate`; OpenCode lanes lose shell inline config).
