Less stored data, a config grouped by what it is about, and fewer things obor does that nobody chose.

- **Config shape 2:** `.obor/config.json` has ten top-level keys (`project`, `lanes`, `agents`, `rules`, `merge`, `nightly`, `commands`, `checks`, `reviews`, `version`) in place of 24, with names that say what they are (`slots` is now `checks.heavy_at_once` and `checks.cpus_per_check`; `lanes` and `lanes_dir` are `lanes.count` and `lanes.dir`). Serve rewrites and commits each project's config once at its first start; `obor config migrate` does it by hand. The old shape is read for this release only.
- **A passing step leaves no log:** only a failure writes a step log, and a task's logs go when the task ends. Nightly failure logs stay until that step passes again.
- **Nightly cleanup:** backups are gzip'd (about 5× smaller, 7 days kept, only after a successful backup), and files of removed lanes, agents and features are swept. The shim keeps only the current and the previous release binary.
- **Smaller, faster store:** records of tasks that ended over 30 days ago are pruned in the nightly backup (store schema 14), prompts are kept 3 days, and serve's start no longer grows with the number of agent sessions.
- **No model or agent names in commits:** `merge.trailer` is gone, merge messages lose the spec's `Model:` line and lane commits their "Implemented by" line.
- **Pane restore is serve's alone:** the `obor.events` herdr plugin is gone; serve restarts its panes when herdr comes back and at its first start after a herdr restart.
- **An agent cannot end its turn while its own background run is still going**, so a result can no longer be lost behind a "finished" line.
- **Pushing:** a person's shell with no obor role may `git push` without `OBOR_ALLOW_PUSH`; agents still need `rules.may_push`. `/obor:role` is gone: start a role with `obor setup role`.
- **OpenCode needs its plugin named:** a config that uses OpenCode must set `agents.kinds.opencode.plugin` (`obor setup agents` does it).

Upgrading: run the block in `docs/UPGRADE-v0.33.md` (it unlinks the old herdr plugin), then restart serve; it rewrites your config in shape 2 and commits it. Rolling back means restoring a pre-upgrade backup within 7 nights and reverting that commit.
